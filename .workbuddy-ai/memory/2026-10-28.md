## Bug fixed: warranty invoice edit could not be saved ("[object Object]")

Client report: editing a warranty invoice → "Unable to save warranty invoice: [object Object]";
Download PDF worked. Root cause found and fixed.

**Cause (two parts):**
1. `WarrantyInvoiceFormPage` seeds the form with `values: {...data.old, items: ...}` where `data.old` came
   from `select('*,warranty_invoice_items(*)')`. So the form state carried the embedded
   `warranty_invoice_items` array (plus `id`/`created_at`/`customer_id`). The save did
   `const {items, ...head} = form` then `payload = {...head}` → PostgREST received a
   `warranty_invoice_items` key, which is not a column → PGRST204. Only EDIT failed; CREATE was fine
   because `data.old` is null there.
2. `onError` used `String(error)`; PostgrestError is a plain object, not an `Error`, so the toast printed
   `[object Object]` and hid the real message.

**Fix applied (2 files):**
- `src/lib/format.ts`: added `errorMessage(unknown)` — unwraps Error, PostgrestError `{message,details,hint,code}`,
  falls back to JSON. Reuse this everywhere instead of `String(error)`.
- `src/pages/WarrantyInvoiceFormPage.tsx`: replaced `{...head}` spread with an explicit column whitelist;
  `onError` now uses `errorMessage`.
- Bonus hardening: edit used to delete all items BEFORE inserting replacements (a failed insert would leave
  the invoice with zero items). Now captures old item ids, inserts new rows first, then deletes the old ids.

`tsc -b` and `npm run build` both pass after the change. Verified the diagnosis with a node simulation
(`C:/tmp/proof-warranty-bug.mjs`) reproducing both the bad payload key and `String(pgError) === "[object Object]"`.

**Note:** `src/lib/sharePdf.ts` still has `String(error)` in a console-only `errorMessage` field — cosmetic, not user-facing.
